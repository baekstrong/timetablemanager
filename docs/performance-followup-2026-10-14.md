## API와 캐시 범위

`GET /.netlify/functions/analytics/monthly?month=YYYY-MM`은 요청마다 Firebase ID 토큰을 검증한다(캐시 hit도 포함). 기존 signed-in records 읽기 권한과 같은 범위의 월 통계만 제공한다. 응답은 `{month, generatedAt, students}`이며 원본 세트나 메모를 반환하지 않는다. HTTP 응답은 `private, no-store`, CORS는 Authorization과 OPTIONS를 지원한다.

서버 warm 인스턴스에서 월별 완료 결과를60초 재사용하고 동일 월의 진행 중 요청을 공유한다. `refresh=1`은 완료 캐시를 우회하되 진행 중인 요청에는 합류한다. 서로 다른 함수 인스턴스/콜드스타트는 캐시를 공유하지 않는다. **서버 cache miss에서는 여전히 해당 월의 원본 문서를 읽는다.** DB 문서 읽기가 영구적으로 없어지는 materialized 집계는 아니며 데이터 마이그레이션·트리거·새 쓰기를 추가하지 않았다.

공유 브라우저 클라이언트는 토큰·결과를 별도 저장하지 않고 진행 중 요청만 공유한다. 토큰 취득을 포함해20초 제한, 계정 전환 시 결과 거부, 오류 재시도를 제공한다. 도장에서는 실패를0명/0일로 표시해 확정하는 것을 차단한다. 메모는 계정·코치·학생별30초 메모리 캐시를 쓰며 실패는 캐시하지 않는다.
