# 수업 음성 메모 자동화 검토 (2026-10-22)

> 상태: **검토만 완료**. 코드·운영 데이터 변경 없음. 실제 수업 녹음 인식 테스트 전.

## 목적
수업 중 수강생 특이사항을 메모하는 걸 자꾸 잊는다. 녹음만 하면 AI가 수강생별 특이사항을 정리해 보고하고, 코치가 고른 항목만 메모로 남기게 한다.

## 결론
- 가능하다. **별도 앱 개발은 필요 없다.**
- 워치 앱을 새로 만들지 않고 기본 '음성 메모'를 쓴다.
- AI 분석은 API 키 대신 **Claude 구독(OAuth 로그인)의 Claude Code**가 맡는다.

## 구성
| 단계 | 방법 | 개발 |
|---|---|---|
| 1. 녹음 | 아이폰(또는 애플워치) 기본 '음성 메모'. 수업 시작 시 한 번 누름 | 없음 |
| 2. 전송 | iCloud로 Mac 음성 메모에 자동 동기화. 파일 위치: `~/Library/Group Containers/group.com.apple.VoiceMemos.shared/Recordings/*.m4a` | 없음 |
| 3. 받아쓰기 | Mac에서 Whisper 실행(무료). Claude는 음성 파일을 직접 못 읽으므로 필수 | 짧은 스크립트 1개 |
| 4. 분석·보고 | Claude Code가 받아쓴 내용 + 이 앱의 해당 교시 명단(`studentMeta/roster-*`)을 보고 수강생별 특이사항 정리 | 스킬(지시문) 1개 |
| 5. 메모화 | 채팅에서 고른 항목만 훈련일지/수강생 메모에 저장 | 기존 저장 경로 재사용 |

- 비용: 받아쓰기 0원, 분석은 구독 사용량 안에서 처리.

## 역할 분담
- **Mac(macOS 기본 폴더 감시 + 스크립트)**: 새 녹음 감지 → Whisper 받아쓰기 → Claude Code 호출. 여기까지만 한다.
- **Claude Code(구독 로그인)**: 교시 매칭·분석·제안·코치 선택 반영·앱 저장까지 실제 작업의 대부분을 한다.

## 상세 흐름 (2026-10-22 결정: 수업이 끝날 때마다 분석)
1. **녹음(코치)**: 아이폰 '음성 메모'로 수업 시작·종료 시 녹음/정지. 특이사항은 "메모, 김OO님 오른쪽 어깨 통증"처럼 이름을 붙여 말한다. 아이폰·Mac 모두 iCloud 음성 메모를 켠다.
2. **감지(Mac, 자동)**: 녹음이 Mac 폴더에 동기화되면 폴더 감시가 받아쓰기를 바로 실행하고, 끝나면 Claude Code를 자동 실행한다. 수업 종료 시각이 아니라 **녹음 파일 도착**이 기준이므로 수업이 늦게 끝나도 맞게 동작한다. 코치가 하는 일은 녹음 정지와 선택뿐이다. 이 시점에는 앱에 아무것도 저장하지 않는다.
3. **교시 매칭(Claude Code, 자동)**: 녹음 시작 시각으로 교시를 판정한다(예: 19:52 → 5교시 19:50~21:20). 그날 그 교시 명단은 `studentMeta/roster-YYYY-MM-DD`에서 가져온다. 수업 시간 밖에서 시작한 녹음은 "교시 확인 필요"로 표시한다.
4. **분석·제안(Claude Code, 자동, 수업마다)**: 받아쓰기가 끝나면 그 수업 하나에 대한 수강생별 제안을 만들고 Mac 알림을 보낸다. 수업 종료 후 약 5~10분(동기화 1~3분 + 받아쓰기 몇 분 + 분석 약 1분)이 걸린다. 4·5교시처럼 쉬는 시간이 20분이면 다음 수업 초반에 도착할 수 있다.
   ```
   📋 10/22(수) 5교시 19:50 · 6명

   김OO
    1. [운동·벤치프레스] 그립 한 뼘 넓게, 팔꿈치 45도      → 운동 메모(수강생 보임)
    2. [전반] 오른쪽 어깨 통증 언급, 오버헤드 프레스 중단   → 코치 전용 메모
   이OO
    3. [운동·데드리프트] 60kg 처음 성공, 다음엔 62.5kg     → 운동 메모(수강생 보임)
   박OO
    4. [전반] 다음 주 출장으로 결석 예정                  → 코치 전용 메모

   저장할 번호를 알려주세요. (예: 1, 3 / 전부 / 없음 / "2번 운동 메모로")
   ```
5. **선택(코치)**: 수업마다 바로 골라도 되고, 쌓인 제안을 나중에 한꺼번에 골라도 된다. 문구 수정과 저장 위치 변경도 가능하다. 답하기 전에는 저장하지 않는다.
6. **저장(Claude Code, 자동)**: 고른 항목만 구분에 따라 기존 저장 위치에 덧붙인다. 저장 후 해당 녹음·받아쓰기 파일은 삭제한다.

> **최종 결정 갱신 (2026-10-22 저녁): 저장 대상은 코치 전용 메모 + 수강생 체크리스트(`coachPinnedMemos`) 두 가지.** 훈련일지의 코치 운동 메모를 운동별 체크리스트(수강생이 체크하면 done으로 숨김)로 바꾼 뒤 포함하기로 했다. 제안은 확인 페이지(127.0.0.1:5179)에서 **체크로 컨펌**한 것만 저장한다. 아래 '코치 전용 메모 하나뿐' 결정은 이력이다.
>
> 이전 결정 (2026-10-22): 저장 대상은 코치 전용 메모(`coachNotes/notes`) 하나뿐이다. 코치는 수업 중 이 메모만 본다. 운동별 내용도 별도 운동 메모(`coachPinnedMemos`)에 쓰지 않고, 코치 전용 메모의 해당 부위 덩어리 안에 운동 이름과 함께 적는다. 아래의 운동 메모 저장 위치·예시는 검토 이력이다.

### 메모 구분 (2026-10-22 사용자 요구: 수강생별·운동별)
제안은 **수강생별로 묶고**, 항목마다 **운동별/전반**을 구분한다. (저장 위치는 위 최종 결정을 따른다.)

| 구분 | 예 | 저장 위치 | 앱에서 보이는 곳 | 수강생 노출 |
|---|---|---|---|---|
| 운동별 | 벤치 그립, 데드 중량, 스쿼트 깊이 | `coachPinnedMemos/{수강생}.memos[{exercise, memo}]` — 같은 종목이 있으면 줄바꿈으로 덧붙임(훈련일지 피드백 고정과 같은 병합 방식) | 훈련일지에서 그 종목을 고르면 뜨는 운동 메모 카드 | **보임** |
| 전반 | 통증·부상, 결석·일정, 생활 | `coachNotes/notes.map[수강생]` — 기존 메모 뒤에 `[10/22] …` 추가 | 코치 첫 화면·훈련일지 코치 전용 메모 | 안 보임 |

### 중점 기록: 통증과 처방 (2026-10-22 사용자 요구)
가장 중요하게 뽑을 내용은 **어떤 운동에서 어디가 아픈지**와 **그걸 해결하려고 코치가 어떤 운동을 하라고 했는지**다. 분석은 이 쌍을 1순위로 찾고, 나머지(중량·자세 지적·일정)는 그 아래에 둔다.

- 한 항목 = `수강생 / 아픈 운동 / 부위·증상 / 처방(대체·교정 운동, 지시)`.
- 통증은 말했는데 처방이 녹음에 없으면 "처방 없음"으로 표시해 코치가 빠뜨린 걸 알 수 있게 한다. 처방만 있고 통증 맥락이 없으면 "이유 확인 필요"로 표시한다.
- 같은 수강생의 이전 코치 전용 메모에 같은 부위 기록이 있으면 "이전: 10/8 같은 부위"처럼 재발을 함께 보여준다.

```
김OO
 1. [통증] 스쿼트 — 왼쪽 무릎 안쪽 통증(내려갈 때)
    처방: 박스 스쿼트로 대체, 밴드 클램쉘 15회×3
    이전: 10/8 왼쪽 무릎
    → 코치 전용 메모: 전체 기록
    → 운동 메모(스쿼트): "무릎 아프면 박스 스쿼트 + 밴드 클램쉘 15×3"
```

- 저장 기본값: 통증·처방 전체는 **코치 전용 메모**에 남긴다. 처방 부분은 수강생이 다음에 그 운동을 고를 때 보도록 **아픈 운동의 운동 메모**에도 함께 제안한다(수강생 본인 카드에만 보임). 코치가 선택 시 한쪽만 저장하도록 바꿀 수 있다.
- 녹음 습관: "김OO님, 스쿼트 할 때 왼쪽 무릎 → 박스 스쿼트로 바꾸고 클램쉘 15개 3세트"처럼 **이름·운동·부위·처방**을 한 번에 말하면 정확도가 가장 높다.

### 메모 형식: 날짜별 누적 대신 문제별 현재 상태 (2026-10-22 사용자 요구)
날짜별로 계속 덧붙이면 메모가 길어져 오히려 안 보게 된다. 그래서 코치 전용 메모는 **덧붙이지 않고 고쳐 쓴다.**

- 한 문제(부위) = 한 덩어리. `[부위] (시작 시기~, 최근 날짜)` 아래에 `증상 / 추정 원인 / 지금 처방 / 다음 확인` 4줄로 유지한다.
- 새 녹음 내용은 해당 덩어리의 줄을 갱신한다. 같은 내용은 합치고, 끝난 처방·해결된 증상은 지운다. 새 부위만 새 덩어리를 만든다.
- 제안할 때는 **현재 메모 → 바뀔 메모**를 함께 보여주고 바뀌는 부분을 강조한다(빠지는 줄 `-`, 새로 생기는 줄 `+`, 줄 안에서 새로 들어간 말 표시). 코치가 승인해야만 저장한다.
- 덮어쓰기 전에 원래 메모 전체를 로컬 백업 파일로 남긴다(앱에는 이전 버전 기능이 없음).
- 저장은 해당 수강생 키(`map.<이름>`)만 갱신하고, 읽은 뒤 다른 기기가 문서를 바꿨으면 `updateTime` 조건으로 저장을 막는다. 저장 후 다시 읽어 값 일치와 다른 수강생 메모 보존을 확인한다.
- **수강생 본인이 쓴 메모(`pinnedMemos`)는 읽기만 하고 절대 수정·삭제하지 않는다**(사용자 결정). 쓰기 대상은 코치 전용 메모(`coachNotes/notes`)뿐이며 `coachPinnedMemos`도 건드리지 않는다. 수강생 메모에 오래된 내용이 보여도 제안에 참고로만 언급한다.

- 운동 이름은 공용 `exercises` 목록의 이름으로 맞춘다. 목록에 없으면 제안에 "종목 확인 필요"로 표시한다.
- 통증·부상 내용 자체는 특정 운동 중 나온 말이어도 기본값을 **전반(비공개)**으로 한다. 수강생에게 보여야 하는 운동 지시·처방만 운동별로 제안한다(아래 중점 기록 참고). 코치가 선택 시 위치를 바꿀 수 있다.

- 녹음이 처리되려면 Mac이 켜져 있어야 한다. **잠자기 중 쌓인 녹음은 깨어난 뒤 한꺼번에 처리한다**(2026-10-22 사용자 결정). 처리한 녹음 목록을 기록해 두고, 깨어날 때·주기적으로 미처리 녹음을 모두 찾아 수업(교시)별로 제안을 만든다.

## 위험·제약
1. **체육관 소음**(음악·원판 소리) → 인식률 저하 가능. 워치가 손목에 있어 코치 목소리는 잘 들어가지만 수강생 목소리는 약하다. **실제 수업 녹음으로 먼저 검증해야 한다.**
2. **누가 말했는지 구분이 약하다** → 운영 습관으로 해결: "OO님, 오른쪽 어깨 통증"처럼 이름을 붙여 말한다.
3. **개인정보**: 통증·부상은 건강정보(민감정보)다. 녹음 사실을 알리고 동의를 받는다. 분석 후 녹음 파일은 삭제하는 것을 기본으로 한다. 위키/문서에 개인 기록을 남기지 않는다.
4. **녹음 시작은 직접 눌러야 한다**(워치가 마이크를 자동으로 켤 수 없음). 필요하면 수업 시작 알림을 추가한다.
5. `studentMeta/roster-*`는 코치가 조회한 주의 시간표 파생 명단이므로 실제 출석 증거로 단정하지 않는다.

## 1차 실녹음 테스트 (2026-10-22 목 2교시, 수강생 2명)
- 아이폰 음성 메모 82분 → m4a 40MB(약 0.5MB/분). Mac 동기화 정상.
- 받아쓰기: `whisper-cli` + `ggml-large-v3-turbo`(1.5GB, `~/.local/share/whisper-models/`), 82분에 **336초**. 임시 wav(16kHz, 150MB)와 복사본은 처리 직후 삭제.
- 권한: Claude 앱에 **전체 디스크 접근 권한**을 켜야 음성 메모 폴더(`Operation not permitted`)를 읽을 수 있다. 원본 삭제는 iCloud 동기화 때문에 음성 메모 앱에서 하고 설정 '삭제된 항목 지우기: 즉시'를 권장한다.
- 명단: `studentMeta/roster-2026-10-22`의 `2`교시 2명. REST 값 파싱 시 `map` 필드를 한 번 더 감싸지 않도록 주의(처음에 빈 명단으로 잘못 읽음).
- 품질
  - 쓸 만함: 통증 부위·코치 설명·처방(마사지, 폼롤러 10초 누르기, 대체 운동, 맨메이커 12분 테스트 기준)은 문장 단위로 대부분 복원됐다. 기존 코치 메모(거위발건·외측광근)와 대조해 재발 판단도 가능했다.
  - 문제1 **반복 환각**: 조용한 구간에서 같은 문장이 수백 줄 반복(2,438줄 중 약 52%). 연속 중복 제거로 정리했으며, 다음엔 `--max-context 0`/VAD 옵션을 시험한다.
  - 문제2 **이름 오인식**: 등록 이름과 다르게 받아쓴 경우가 있어 명단과 비슷한 이름으로 맞춰야 한다.
  - 문제3 **"여기·이거" 지시어**: 운동·부위 이름 없이 손짓으로 말한 부분은 어느 운동·어느 쪽인지 복원되지 않았다. 화자 구분이 없어 누구 얘기인지 불분명한 항목이 생겼다 → "수강생 확인 필요"로 제안.
  - 명단 원칙(사용자 확인): **`김기안`은 테스트 계정이므로 명단에서 항상 제외**한다. roster는 결석 신청 없이 빠진 사람도 남는 후보 목록이지 출석 증거가 아니다. 테스트 실제 출석은 정찬화님 1명이었다. 녹음에서 이름이 한 명만 나오거나 코치가 인원을 말하면 그 기준으로 전 항목을 배정한다.
  - 이름 추정(사용자 결정): 이름은 잘 안 들릴 수 있으므로 "확인 필요"로 비워두지 말고 **명단에서 가장 비슷한 이름이나 대화 맥락(이전 메모의 같은 부위 등)으로 추정해 채운다.** 추정한 이름에는 `(추정)`을 붙여 코치가 선택할 때 바로잡을 수 있게 한다.
  - 코치 본인 이야기 제외(사용자 확인): 코치도 수업 중 자기 몸 이야기를 한다. 1차 테스트의 "왼쪽 손목 당김·왼쪽 어깨 불편(메이스벨 왼손)"은 수강생이 아니라 **코치 본인** 이야기였다. "저는/제가/제 어깨" 같은 1인칭 경험담, 설명용 예시, 다른 사람 사례는 수강생 메모로 제안하지 않는다. 애매하면 제안하되 "코치 본인 이야기일 수 있음"을 표시한다.
  - 첫 실제 저장(사용자 승인): 정찬화님 코치 전용 메모를 날짜별 3줄 → `[오른쪽 무릎·거위발건]` 한 덩어리(증상/추정 원인/지금 처방/다음 확인)로 고쳐 저장. 원본은 `outputs/class-voice-memo-2026-10-22/`(커밋 제외, mode 600)에 백업. 저장값 일치·다른 수강생 25명 메모 보존 확인. 운동 메모·수강생 메모는 변경하지 않음.
  - 코치 수정본 반영(사용자 문구 그대로 저장): AI 제안과 달라진 점이 다음 분석의 기준이다.
    - 원인 용어: AI는 "내전근 약함"으로 일반화했지만 코치 판단은 **"거위발건 근육 약함"**. 코치가 이미 쓰는 용어·이전 메모의 표현을 우선한다.
    - 그날 일시적 증상(힙힌지 굽힐 때 당김)과 그 자리 처치(허벅지 안쪽·뒤쪽 마사지, 폼롤러 방법)는 **현재 상태 요약에서 빠졌다** → 수업 중 1회성 대응은 제안하지 않거나 낮은 우선순위로 둔다.
    - 녹음에서 못 찾은 처방(**교정 레그컬**)과 다음 단계(**통증 지속되면 코펜하겐 플랭크**)를 코치가 추가했다 → "처방 없음"으로 표시한 항목은 코치가 채울 칸으로 남기는 게 맞다.
    - "다음 확인"의 지난 계획(장요근 강화, 내측광근 레그 익스텐션)은 지웠다 → 끝났거나 바뀐 계획은 남기지 않는다.
  - 결론: 흐름은 성립한다. 정확도를 좌우하는 건 녹음 습관(**이름·운동·부위·처방을 말로**)이다.

## 코치 전용 메모 한 줄 형식 (2026-10-22 밤 사용자 결정)
- 블록 형식(증상/추정 원인/지금 처방/다음 확인)은 너무 길어 안 읽게 된다 → **문제 하나 = 한 줄 `문제 -> 해결책`**. 예: `벤치할 때 잘 안 내려가짐 -> 쉬는 시간에 헤일로 양쪽 3회씩`.
- 같은 문제 줄은 고쳐 쓰고, 해결책을 못 찾으면 `-> (처방 미정)`. 코치가 직접 쓴 기존 긴 메모는 건드리지 않는다. 규칙 정본은 `RULES.md`.

## 화자 구분·이름 매칭·성문 (2026-10-22 밤 구현, 기본 꺼짐)
- 사용자 요청: 화자 구분 검토 → 코치가 이름을 부른 뒤 대답한 목소리와 이름 매칭 → 다음 수업용 성문까지 구현.
- 시험(4교시 86분, 명단 6명): sherpa-onnx pyannote 화자 구분은 **713명으로 쪼개지고** 실행 9분이라 폐기. whisper 줄 단위로 목소리 특징값(3D-Speaker ERes2Net, 68초) + 평균 연결 코사인 군집으로 교체(`diarize.py`, 임계값 0.8).
- 정확도: 코치/그 외 구분은 지시형 문장 기준 **70~88%**로 깔끔하지 않음. 코치가 이름을 부른 횟수가 적어 표가 2~4개뿐이고, 수강생 목소리끼리 섞임(한 목소리에 여러 사람 대화). 폰이 코치 몸에 있어 수강생 목소리가 멀고 작으며 체육관 소음이 큼.
- 결론: 틀린 이름이 분석을 오도할 위험이 더 커서 **기본 꺼짐**. 켜기: `touch ~/Library/Application\ Support/ClassVoiceMemo/diarize.on`. 켜면 줄마다 `[코치]/[이름]/[이름?]/[다른 사람N]`이 붙고(`RULES.md`의 화자 표시 절), 이름 표 2개 이상·60% 이상인 목소리만 성문에 누적 평균 저장, 이름 표가 없는 목소리는 오늘 명단 중 성문 유사도 0.6 이상이면 `이름?`으로 추정.
- 성문은 **생체정보**: 이 Mac의 `~/Library/Application Support/ClassVoiceMemo/voiceprints.json`(600)에만, Firestore·Git·위키 금지. 켜서 쓰려면 수강생 명시 동의가 필요하다(개인정보보호법상 민감정보).
- 정확도를 올리려면: 코치가 이름을 더 자주 부르기, 녹음 기기를 코치 몸이 아닌 수업 공간 가운데 두기 등 녹음 조건 개선 후 재시험.
- 설치: `~/.local/share/class-voice-memo/venv`(sherpa-onnx, numpy, scipy), 모델 `~/.local/share/class-voice-memo/models/`.
