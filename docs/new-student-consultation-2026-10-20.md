# 신규 주4회 제한·상담 접수 (2026-10-20)

## 현재 상태

- 사용자 시안 승인으로 로컬 구현·검증 완료. 후속 요청으로 **웹 미리보기 확인 전 main 푸시/Pages 및 Firestore 운영 규칙 배포 보류**.
- 사용자 정정: 표시 문구는 `4주`가 아니라 **`주4회 등록 원함`**. 상담 체크 후 `주4회 등록을 원합니다`를 추가로 체크한 요청만 빨갛게 강조한다.
- 운영 데이터 변경·실제 문자/푸시 발송 없음. 미리보기는 `demo-strength` 로컬 에뮬레이터와 기존 UI를 사용한다.

## 동작

- 신규 신청의 주4회 카드: 가격 대신 `상담 후 신청 가능`, 선택 불가. 주2/3회 직접 신청 및 기존 후반의 일반 상담 여부 선택은 유지한다.
- 첫 일정 화면 `상담 신청하기` 체크: 시간표·입학반·결제 선택 없이 이름(최대50자), 010 연락처, 선택 상담 내용(최대1000자)으로 상담만 신청한다. 추가 체크 `주4회 등록을 원합니다`는 기본 해제 상태다. 상담 체크를 해제하면 원래 신청 내용으로 돌아간다.
- 접수 중 중복 클릭/입력/모집월 변경을 막고, 성공 후 완료 화면을 표시한다. 필수 입력 누락·잘못된 연락처·모집 마감·저장 실패는 성공 처리하지 않는다. 동일 화면 재시도는 동일 문서ID를 사용해 상담 문서를 중복 생성하지 않는다. 저장 성공 뒤 응답 유실 시에는 공개 조회/업데이트가 금지되어 재시도에 오류가 나올 수 있다.
- 코치 신규 관리의 `상담 요청` 필터: 대기 상담 우선, 주4회 희망자는 카드 상단에 빨간 문구/옅은 빨간 배경. 전화 링크·상담 내용·삭제·상담 완료 제공. 상담 요청을 수강 승인하거나 좌석을 잡는 버튼은 없다. 대기 상담을 신규 관리 알림 건수에 포함한다.
- 상담 요청은 SMS 자동 발송 대상이 아니다. 기존 신규 신청 문자/결제/승인/코치 직접 주4회 등록은 기존 경로를 유지한다.

## 저장과 규칙

- `recruitmentConsultations/{id}`: `recruitmentMonth`, `name`, `phone`(숫자11자리), `message`, `wantsFourTimes`(boolean), `status`(pending/completed), `createdAt`, `updatedAt`.
- 실제 `consultationService`가 트랜잭션으로 최신 모집 설정을 읽고 open인 현재/미래 모집월에서만 생성한다. 명시한 필드만 저장하고 수강 시간·비용·비밀번호를 저장하지 않는다.
- Firestore 규칙: 상담 생성 스키마·모집월·서버 시간 확인, 상담 조회/완료/삭제는 코치만 허용. 기존 신규 신청 공개 생성은 주2/3회만 허용하고 코치의 직접 등록·기존 후속 수정 권한은 유지한다.
- 배포 재개 시 실제 `traininglogforclients` 운영 규칙을 다시 읽고 변경분만 병합/검증한 뒤 규칙을 먼저 배포하고 프론트 main을 푸시한다. `.firebaserc` 기본 프로젝트를 사용하지 않는다. 기존 운영 규칙/새 규칙의 차이와 Pages 배포 결과를 확인한다.

## 검증

- 전체 Vitest **104파일945테스트**, 관련3파일42테스트 통과.
- 로컬 Firestore REST 규칙 **39테스트** 통과: 주2/3회 정상 생성, 주4회 일반/만석 직접 생성 거부, 코치 주4회 등록 유지, 상담 생성/입력 제한/마감/지난월/추가 필드 차단, 학생/비로그인 조회·완료·삭제 거부, 코치 조회/완료/삭제.
- 프로덕션 build 통과. 변경 JSX/서비스 lint 오류0, 기존 effect 의존성 경고2 유지. diff 공백 검사 통과.
- 실제 React UI + 실제 상담 서비스 + 로컬 Firestore: 상담 체크→주4회 추가 체크→예시 정보 접수→완료→코치 빨간 강조→상담 완료 상태 변경 확인. 일반 주2회 2개 시간 선택→정보 단계 이동 확인. 320px 화면에서 신청 카드·체크·입력 표시 확인 후 좁은 가격 줄바꿈 보완. 코치 필터5개는 모바일에서 두 줄로 배치해 빨간 강조/내용/완료 버튼이 가로 넘침 없이 보임을 확인.
