# 진행 중 계약변경

2026-10-19 사용자 요청: 코치 수강생 관리에 계약변경을 추가한다. 소진은 자동 계산하며 Sheets F열에는 `계약변경`, I열에는 추가 결제액(만원)을 기록한다. 이전 신규/재등록의 D열만 비우고 G/H와 원결제를 보존한다. 이전 E열에는 `26.10.19에 주2회 → 주4회로 수강 변경 함`처럼 날짜·변경 횟수를 기존 메모 뒤에 추가한다.

## 동작

- 현재 이용 중인 등록을 선택해 주2/3/4회·요일/교시·추가 결제액·결제일/방식/완료 여부를 설정한다. 총회차는 기존 등록 개월을 유지한 새 주횟수×4×개월이다. 기본 차액은 표준 주횟수별 요금 차이×개월이며 직접 조정할 수 있다. 환불은 별도 업무다.
- 원래 종료일까지 남은 유효 수업을 기존 시간표·시트 합의결석·휴일·홀딩·보강으로 계산하여 기소진을 구한다. 일반 학생 결석은 기존처럼 소진한다. 당일 교시가 끝나기 전에는 기소진하지 않으며 이미 지난 새 교시를 소급 생성하지 않는다. 실제 훈련일지 작성 횟수를 출석 체크로 단정하지 않는다.
- 새 잔여를 변경 적용일부터 새 시간표에 배치해 H를 구한다. 기예약 보강의 원수업 슬롯이 유지되면 기존 이동을 사용하고, 원수업이 이미 지났거나 교시가 달라지면 해당 보강을 별도 잔여로 보존한다. 미래 홀딩도 반영하며 M/N/O 사용 이력은 그대로 복사한다. 새 행의 G는 원래 등록 시작일이다.
- 예시 합성 등록: 10/19 월4 종료 후 주2→4회, 월4목1→월4수4목4금4, 총16·소진1·잔여15·추가14만원·종료11/13. 실제 운영 조회·수정 결과가 아니다.
- 모든 월별 등록에서 이전에 시작한 신규/재등록/계약변경의 D를 비운다. 미래 미리 등록은 보존한다. 새 종료일이 다음 계약과 겹치면 다음 등록 조정 안내로 저장을 막는다.

## 저장과 이력

`POST sheets/contractChange`는 원본 스냅샷을 다시 대조하고 `spreadsheets.batchUpdate` 한 번의 `updateCells(D/E)`+`appendCells(A:R)`로 저장한다. 새 행 위치를 미리 정해 다른 등록을 덮어쓰지 않는다. 번호·주횟수·날짜·결제액은 숫자로 저장해 시트 SUM 집계를 유지한다. 같은 변경ID의 재요청은 새 행을 또 만들지 않는다. 네트워크 응답 유실은 자동 재전송하지 않고 최신 조회를 요구한다. 원본 읽기와 쓰기 사이의 여러 기기 동시 수정까지 Sheets CAS 트랜잭션으로 보장하는 것은 아니다.

이전 E에는 읽기 쉬운 변경 메모와 원래 시간표/연결ID가, 새 E에는 변경 구간·소진 기준·보강 스냅샷을 담은 내부 태그가 보존된다. 이 태그는 변경 전 수업을 새 시간표로 다시 만들지 않기 위한 근거다. 비밀값/추가 개인정보는 넣지 않는다.

## 내정보와 시간표

시간표가 있는 등록이 있으면 D가 비워진 이전 행은 현재 등록 선택·쓰기 대상·현재+미리등록 합산에서 제외한다. 이전 G/H가 동일해도 계약변경 행이 선택된다. 결제/원본 이력은 삭제하지 않는다. 내정보의 총회차·소진·잔여·등록개월·홀딩이 중복 합산되지 않으며 계약변경에 한해 날짜별 이전 시간표·선택 홀딩·기예약 보강을 사용한다. 과거 출석 내역·오늘 주간 수업·코치 시간표도 변경일 전 시간표를 사용한다. 홀딩 취소/영구 시간표 변경의 전체 재계산은 계약변경 기준일과 이전 소진을 사용한다.
