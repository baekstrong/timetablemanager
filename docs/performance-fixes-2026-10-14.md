# 첫 로딩·훈련일지 성능 개선 — 2026-10-14

첫 화면에서 기다리는 작업을 분리하고, 반복 조회와 느린 인증 복원 때문에 늘어나던 추가 요청을 줄였다. 사용자 요청의 우선 4개와, 다른 화면에서 발견한 조회 중복을 함께 수정했다. 정상 세션·등록·홀딩·여석 검증은 유지한다.

## 1. 첫 화면의 불필요한 직렬 대기 제거

- 학생 화면을 즉시 마운트하여 개인 보강 3개 조회를 공통 주간 조회·전체 명단과 동시에 시작한다.
- 본인 수업을 판단할 데이터가 준비되면 내 일정을 표시한다. 전체 명단이 늦어도 본인 조회를 다시 기다리거나 반복하지 않는다.
- 전체 명단·휴강·잠금·주간·개인 데이터가 준비되기 전에는 여석 표시와 신청·승인을 제한한다. 조회 실패를 정상적인 빈 명단이나 빈 설정으로 처리하지 않는다.
- 본인 수강권이 전체 명단보다 먼저 도착해도 홀딩의 선택 날짜를 보존한다. 현재/미리 등록과 오래된 결제월 조회의 `requireActive:true`는 유지한다.
- 코치 첫 화면에는 제목·수업 영역을 먼저 표시한다. 실제 수업 및 자동 처리에는 필요한 준비 조건을 유지한다.

## 2. 과거 시트와 앱 복귀의 중복 조회 제거

- 과거 정지 회원 B:H 조회에 30초 캐시와 진행 중 요청 공유를 적용한다. 기존 A:R 전체 필드 캐시와 분리했다.
- 모든 관련 쓰기에서 두 캐시를 무효화한다. 저장 이전의 늦은 응답이 새 캐시를 덮지 않도록 세대 번호를 확인한다.
- 시트 범위와 회원 검색 범위를 줄이지 않는다. 현재 등록이 오래된 시트에 있는 회원을 놓치지 않는다.
- 코치의 다른 앱→복귀 갱신은 60초 간격 및 진행 중 요청 제한을 적용한다. 오늘↔시간표 이동은 동일 계정·날짜의 컴포넌트를 유지한다.

## 3. 훈련일지 인증·달력·기록 진입 개선

- 메인과 훈련일지가 같은 세션 복원 함수를 사용한다. 2.5초 복원 지연을 세션 없음으로 판단해 서버 로그인을 겹쳐 시작하던 경로를 없앴다.
- 실제 세션 없음 또는 계정 불일치일 때만 비밀번호 자동로그인으로 넘어간다. 네트워크 오류나 12초 복원 시한 초과는 저장 정보를 보존하며 다시 확인할 수 있도록 안내한다. 역할은 검증된 토큰 claims로 판정한다.
- 달력 날짜를 먼저 표시하여 조회 중에도 날짜를 선택할 수 있다. 마지막으로 확인한 계정별 날짜·피드백 유무 요약은 갱신 중이라는 문구와 함께 표시한다. 내용 전체는 저장하지 않는다.
- 코치의 선택 학생 기록과 메모를 병렬로 조회한다.
- 메모 구독이 전달한 상태를 다시 그릴 때 같은 문서를 추가 조회하지 않는다.

## 4. 운영 서버의 누락된 성능 설정 반영

Netlify `auth`, `sheets`만 배포했다. 운영 배포 ID는 `6acf5c793114396684f22e5f`이다.

- 두 함수의 실제 OPTIONS 응답에 `Access-Control-Max-Age:86400` 확인.
- Sheets 전용 패키지 및 warm 인스턴스의 인증 클라이언트 재사용 반영.
- Sheets ZIP은 2,951,686 → 495,309바이트, 약 83% 감소. 이는 배포물 크기의 감소이며 사용자 대기 시간의 감소율은 아니다.
- 정적 파일 109개와 calendar/push/sms 함수 digest가 이전 배포와 동일함을 확인했다.
- 운영 Sheets info GET 200 및 정상 응답 확인. 회원 쓰기·실제 로그인·문자·푸시는 검증에 사용하지 않았다.

운영 ZIP 원본을 직접 내려받지 못해 기존 운영 코드와 로컬 드롭의 완전한 바이트 일치는 확인하지 못했다. Auth는 기존 로컬 완성 번들의 헤더만 바꾸고, 기존 핸들러의 로그인·비밀번호 관련 8개 모의 시나리오가 같음을 확인했다. Sheets의 로컬 기존 드롭 소스와 저장소 차이는 패키지·인증 재사용·CORS 관련 6개 diff 구간이었다.
