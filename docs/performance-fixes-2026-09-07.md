# 간헐적 지연 수정 결과 — 2026-09-07

사용자의 전반 점검 후 수정 요청에 따라, 재현된 요청 증폭·경쟁 상태와 반복 계산을 수정했다. 기준 소스는 `d02b2cd`다. 운영 개인정보·발송·데이터 쓰기로 테스트하지 않았다.

시트 총 20초는 **단일 API 요청의 예산**이다. 시트 목록→배치 읽기 등 여러 요청이 연속되는 작업이나 Firebase 토큰 교환 전체가 20초에 끝난다는 뜻은 아니다. 마지막 정상 데이터를 보여줄 때 실패 안내를 함께 표시하며, 저장 실패/응답 불명확을 성공으로 숨기지 않는다.

## 검증

- `npm test`: 38개 파일, **389개 전부 통과**. 실제 함수·훅 본문을 모의 DB/타이머로 실행해 중복·응답 역전·실패 경로 검증.
- 추가 회귀 테스트 20개: 시트 6, 코치 6, 주간 데이터 3, 인증 4, 복귀 조회 1.
- 기존 pauseStudent 테스트는 날짜를 고정해 실행일이 지나도 검증 대상 등록이 사라지지 않게 수정.
- `npm run build`: 성공. 초기 JS gzip **352.49 → 322.77kB(약 8.4% 감소)**, 초기 CSS gzip **16.91 → 12.07kB**. 로컬 빌드 환경 기준이며 실제 사용자 체감 시간의 측정값이 아니다.
- `npm run lint`: 기존 오류로 전체 통과하지 않음. 199 errors / 14 warnings. 변경 파일의 HEAD 버전과 새 파일을 ESLint 결과로 비교했으며 **새로 추가된 오류·경고 0개**.
- React Best Practices의 파생 상태/의존성 기준으로 훅 갱신과 셀 결과 재사용 검토.
- 실제 기기의 로그인·저장·알림은 실행하지 않았다. 운영 데이터 자동 변경이 있는 동선이므로 회귀 검증에는 합성 데이터만 사용했다.

## 배포 범위

프론트엔드와 훈련일지 정적 파일 변경이다. main push는 기존 GitHub Pages 워크플로로 배포된다. Netlify 함수 소스는 변경하지 않았으므로 별도 Netlify 드롭 배포가 필요 없다. 작은 성능 버그 수정으로 별도 관리자봇 공지는 발송하지 않는다(CLAUDE.md 공지 규칙 4항).

## 이번 변경으로 단정할 수 없는 부분

- 실제 제보 기기의 p95·콜드스타트·네트워크 회복 시간은 미측정이다. 전체 로그인/저장/화면 전환이 특정 시간 내 끝난다고 보장하지 않는다.
- 성장 그래프의 과거 이름 호환 폴백, 월별 랭킹/도장의 원본 기록 집계는 유지했다. 이를 없애려면 과거 데이터의 이름 정규화와 집계 데이터 설계가 필요하다.
- Sheets 30초 캐시 자체는 유지했다. 갱신 범위/시간을 무작정 늘리거나 최근 월 창을 줄이면 수강 중 등록 누락·오래된 운영 데이터 노출 위험이 있다.
- SMS·캘린더 완료 처리와 Firestore 저장 ACK의 업무상 순서, 시트/Firestore 이중 쓰기·롤백 규칙은 유지했다.
- 원격 성능 수집 설정은 추가하지 않았다. 후속 측정은 개인정보 없이 화면/작업명, 버전, 캐시 적중, 요청 시간/시도 수, 화면 복귀 여부, Long Task를 분리하는 것이 필요하다.

따라서 이번 결과는 주요 재현 결함의 수정과 부하 절감 완료이며, 모든 사용자 환경의 지연 원인 제거를 의미하지 않는다.
