## 데이터와 처리 경로

- 수강생 주간 요약은 시간표의 `useScheduleCore`가 조회한 보강·홀딩·결석·휴일 데이터를 사용한다. 보강 이동 원본/목적지 표시, 등록 공백 날짜 제외. 신청 판단·저장은 기존 서비스의 기한·쿼터·Sheets/Firestore 처리 규칙을 유지한다.
- 보강 자리 확인은 `StudentSchedule`의 기존 응답 모달/처리 함수를 사용한다. 재등록 계약 및 홀딩·결석은 기존 컴포넌트를 공통 모달에 표시한다. 저장 중 닫기/ESC 차단, 배경 스크롤 잠금·복원.
- 고정 시간 변경은 기존 대기 조회·수락/취소·시트 시간표 변경 서비스를 사용한다. 작업 후 수강생 등록 데이터와 주간 데이터를 재조회한다.
- 오늘 수업의 이름·상태 표시는 기존 코치 시간표의 StudentTag와 공통 CSS를 그대로 재사용한다. 보강이동·보강·홀딩·결석 등은 이름 옆에 별도 상태 칩으로 표시한다(2026-09-23 사용자 추가 요청).
- 코치 좌측에는 오늘 활성 교시 중 명단이 있는 수업을 표시한다. 홀딩·이동 칩은 유지하되 우측 메모 대상에서 제외하고 보강 참석자는 포함한다.
- 실제 시각은 15초 간격으로 확인한다. 교시가 바뀌면 재조회하며, 숨겨진 탭에서 원격 주기 조회하지 않는다. 사용자가 다른 교시를 선택하면 그 선택을 유지하고 실제 현재 교시 강조는 별도로 갱신한다. 날짜가 바뀌면 홈을 새로 구성한다.
- 메모는 훈련일지와 동일한 `coachNotes/notes.map` 문서를 사용하며 학생별 필드만 병합 저장한다. 기존 Firestore `isCoach()` 규칙을 유지한다. 메모 편집 대상 이름은 모달이 열린 동안 고정한다.
- 종료 항목은 이름을 채운 기존 등록 모달을 연다. 미결제 항목은 선택 등록의 시트/행을 재검증한 뒤 J:L 결제 필드만 갱신한다. 신규 항목은 기존 승인 화면의 pending/waitlist 목록으로 이동한다.
